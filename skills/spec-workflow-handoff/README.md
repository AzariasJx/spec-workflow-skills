# spec-workflow-handoff

**跨会话状态交接。** 在 `/clear` 之前生成最小可恢复快照，让下一个会话 5 分钟内回到当前节点。

## 什么时候用

- 对话快到 context 上限，准备 `/clear`
- 要结束今天的工作，明天接着干
- **不用于**：同会话续命（用内置 `/compact`）、跨 agent 派发

## 命令

```
/spec-workflow-handoff [topic]
```

## 产出

- `tmp/<topic>-handoff.md` — 6 段固定结构的交接快照

## 快照结构（6 段）

1. **当前状态**：在做什么、卡在哪、关键产物 status
2. **基线**：git HEAD、关键文件清单、dirty/clean
3. **下一步分叉**：候选方案 + 取舍
4. **关键口径清单**（最重要）：跨 clear 必须保持的决策与不变量
5. **开机动作序列**：新会话第一组动作（有序）
6. **明确不写的**：主动丢弃了什么

## 核心原则

- **不是总结，是开机指令**：主动丢弃探索过程，只留收敛后的状态
- §4 口径密度第一：少于 5 条多半有遗漏
- 不复制文件内容，只写路径

## 特殊

- 不依赖 `.eo-project.json`，任何 git 仓库都能用

## 相关 skill

- 任何 spec-workflow 流程节点都可中途调用
